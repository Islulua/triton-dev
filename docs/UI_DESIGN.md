# triton-dev UI 设计规范

版本：1.0 · 2026-10-27
适用：当前 Web Server 的工作台、环境、测试运行、报告、Profiling、Agent、数据中心和账号设置。
实现入口：`frontend/src/refine.css`；各模块保留自己的结构样式，公共视觉规则最后加载。

## 1. 设计目标

让开发者尽快完成三件事：选择对象、执行操作、判断结果。界面采用浅色背景与青绿色操作色，靠字体、对齐和间距组织信息，减少装饰性卡片和解释性文字。

简约不等于删除证据。首页展示当前任务所需的信息；原始日志、完整 ID、来源快照、统计定义仍通过详情、标签页或导出访问。

### 信息的三个层次

| 层级 | 内容 | 呈现规则 |
|---|---|---|
| 当前决策 | 任务对象、结果、失败数量、耗时、主要操作 | 第一屏直接可见 |
| 当前操作 | 搜索、筛选、Workers、环境选择、配置表单 | 与所作用的列表或对象紧邻 |
| 追溯证据 | 完整 ID、哈希、原始 JSON、日志、统计口径 | 默认折叠或进入专属标签页 |

### 保留与删除原则

- 删除重复标题说明、重复用户名、装饰性英文眉题、全局固定免责声明、已经由控件名称表达的操作教程。
- 一个页面只保留一个新建入口；已有报告优先展示结果，新建表单按需展开。
- 空数据展示一条明确空态，有可行下一步时给出操作入口；不同时显示两套相同操作。
- 未接入模块不在主导航长期放置无效按钮。后续有可操作闭环再加入。
- 错误、取消、超时、数据缺失、模拟来源必须保留；不能为了干净而暗示成功或真实执行。
- 不把日志从证据中删除，只减少默认页面上的直接打印。

## 2. 全局布局

### 应用外壳

- 左侧固定导航，沿用当前 216px / 中屏 190px 结构；主导航图标 20px，文字 14px。
- 顶栏 56px，左侧连接状态，右侧当前用户。删除日期、重复运行模式胶囊和重复姓名。
- 页面标题使用 H1，桌面 26px、窄屏 23px。一般不再添加复述标题的副标题。
- 内容区桌面水平内边距 32px、大屏 40px，移动端 18px；垂直起始 28px / 22px。
- 页面按内容自然向下排布，不用固定高度撑大空白。主要内容之间 24px，相关控件之间 8–16px。
- 抽屉仅承担创建、对比和明细，不代替长报告主页面；沿用现有关闭、焦点与窄屏覆盖行为。

### 工具栏与主操作

页面标题 → 对象选择 / 工具栏 → 状态 / 结果 → 数据列表或图表 → 详情。

同一操作区域至多一个实心主按钮，其他操作使用描边或文字按钮。禁止在顶部、空态、底部重复展示同一主操作；例如尚未收集时只保留空态中的“开始收集”。运行时“取消”替代“运行”，错误放在相关区域附近。

## 3. 字体、间距与组件尺寸

| 项目 | 规则 |
|---|---|
| 字体 | 系统无衬线，中文 PingFang SC / Microsoft YaHei；nodeid、版本、命令使用等宽字体 |
| H1 | 桌面 26px / 窄屏 23px，650 字重，1.3 行高 |
| H2 / H3 | 18px / 14px，600 字重；结果结论可使用 20px |
| 正文 / 表格 | 13px；辅助文字 12px；短来源标签最低 11px |
| 行高 | 正文 1.5–1.7，长说明与日志 1.7–1.9 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px，共用 spacing tokens |
| 按钮 | 桌面最低 34px，窄屏最低 38px；文字 13px，横向 padding 12px |
| 输入 / Select | 桌面最低 36px、窄屏最低 38px；复选框保持原生语义 |
| 表格 | 表头 padding 10×12px，正文 padding 12px；内容决定行高，目标约 44–60px |
| 圆角 | 一般组件 6px，短结果标签 4px |
| 边框 | 1px 中性色，用于结构分隔；避免卡片里面重复套卡片 |
| 阴影 | 默认不使用；弹窗、浮层和抽屉可使用轻阴影 |

不要通过缩小字号消化复杂信息，优先移除重复内容、分组和按需展开。禁止一列文字四处跳行而邻列存在大量空白；长文本允许局部折行，表格和时间线可以在自身容器横向滚动。

## 4. 颜色规则

以下 token 是当前公共样式的事实源。模块新增颜色应先映射语义，再决定是否真的需要新色。

| Token | 色值 | 用途 |
|---|---|---|
| `--ui-canvas` | `#FFFFFF` | 主背景 |
| `--ui-surface` | `#F7F9FA` | 表头、折叠表单、次级区域 |
| `--ui-ink` | `#243847` | 正文、标题、关键值 |
| `--ui-muted` | `#607582` | 时间、单位、辅助说明 |
| `--ui-line` | `#E4E9ED` | 分隔线、表格边界 |
| `--ui-accent` | `#087F82` | 主操作、当前导航、链接、焦点 |
| `--ui-accent-soft` | `#EDF6F5` | 选中区域与轻背景 |
| `--ui-pass` | `#23765E` | PASS / 成功 |
| `--ui-fail` | `#B64448` | FAIL / 失败 |
| `--ui-crash` | `#7548A4` | CRASH；XPASS 使用相同提醒色但文字区分 |
| `--ui-warning` | `#8C641F` | XFAIL、模拟数据来源标签 |
| `--ui-info` | `#326B9A` | 信息、活动状态的扩展语义 |
| `--ui-neutral` | `#687684` | SKIP / INCOMPLETE / 不适用 |

### 状态与图表

- PASS / FAIL / CRASH 等色块同时包含文字，不只依赖颜色。报告单元格使用实心底色与白色文字；一般状态使用浅底深字。
- 青绿色表示可操作和选中，不表示“所有内容均已验证”。成功必须来自具体结果。
- 未运行、缺少数据、未完成与成功分开。空表或未知时间不显示为 0 成功。
- 模拟来源用短文字“演示数据”或“模拟板卡”明确标记；真实 CPU + mock SDK 的范围在回归上下文保留。
- 算子统计中同一结果状态使用稳定色序；Profiling 引擎色用于分类，与 PASS/FAIL 语义分离，保留引擎名称图例。
- 图表需要轴、单位与必要的计量口径。不能把累计 kernel 工时和并行流水线窗口混为一个数。
- 日志保留深色代码区域和等宽字体，不将普通设置页面改成终端风格。

## 5. 各模块设计

### 5.1 工作台

**理念：快速进入任务，而不是展示介绍页。**

- 以选择环境、选择用例、查看结果三个紧凑入口组织主要路径。
- 删除欢迎口号和重复解释区，下面直接接最近运行。
- 最近运行沿用列表，展示名称、环境、结果和时间；空态给出运行入口。
- 页面仍可能包含浏览器示例对象，必须标明来源，不能当作公共数据库环境清单。

### 5.2 环境与制品

**理念：用表格比较版本，用抽屉完成单对象操作。**

- 已保存组合 / SDK 制品使用同层 Tabs，右侧放“比较版本”“创建组合”。
- 搜索紧邻表格，组合名优先；SDK、Python、验证状态、更新时间为辅助列。
- 每个环境只显示一个主要验证状态，删除“已安装 / 导入通过”重复打印。
- 哈希、完整组件版本和原生边界放在快照抽屉。创建组合保留来源、名称、版本字段，避免逐项解释相同变化规则。
- 当前仍为演示的环境操作，用一条来源提示说明，不在每个区块重复提示。

### 5.3 用例与运行

**理念：围绕“收集 → 选择配置 → 设置 Workers → 运行”组织。**

- 顶部选择测试项目，随后为收集与选择 / 运行记录；结果出现后进入运行详情。
- 没有收集结果时只展示收集空态和主按钮，不显示空的历史下拉框及重复收集按钮。
- 有快照后，收集记录和状态紧凑展示；搜索、最近失败筛选紧邻用例列表。
- 执行模式与 Workers 常驻，扩展选项默认折叠。删除每个控件下面的教学段落，保留统一“执行说明”。
- 逻辑用例分组默认收起，展开后单独勾选参数配置；选中数量和运行按钮在列表底部同一行。
- 运行详情以统计总览为默认，阶段、Worker 日志、进程日志、环境快照、附件为标签页。
- 失败项复测为主要动作；全量复测和报告导出为次要动作。复测不改写父运行。

### 5.4 运行统计

**理念：先看结论数字，再按图表进入失败配置。**

- 六项数字保留：配置数、通过、失败、通过率、执行覆盖率、批次耗时。
- 不在每个数字下常驻打印公式；说明保留可访问文本、提示和折叠的统计口径。
- 结果分布 → 各算子 / 失败阶段 → 慢配置 / 复测变化，按诊断使用频率排序。
- 统计只计参数配置的最终状态；阶段结果不重复计数。未覆盖父配置不计为恢复。
- 图表仍可筛选明细，保留导出与清除筛选。

### 5.5 测试报告

**理念：层级紧凑，展开到用户需要的配置。**

- 顶部为项目与运行选择；摘要展示项目、开始时间、批次耗时和结果分布。
- 文件 → 类/用例 → 参数配置；文件和用例默认全部折叠，分组名称、配置数、状态计数同一行。
- 列内必须保留 PASS / FAIL / CRASH 等结果色块。配置行展示参数、结果、起止时间、阶段耗时、Worker、失败阶段和详情。
- 快照、父运行、退出码、完整环境等放入“运行信息与统计口径”；CRASH 判定规则单独折叠。
- 保留搜索、结果筛选、展开全部、折叠全部、完整 HTML / JSON 导出。
- 没有报告时提供“前往运行用例”，不用一大段文字解释技术前置条件。

### 5.6 Profiling

**理念：报告优先，采样配置按需出现。**

- 顶部一条“模拟板卡”来源说明；新建采样表单默认收起。
- 报告标题展示算子与 dtype，次行环境 revision / 采样数量；完整 nodeid 与设备原始信息在元数据页查询。
- 报告记录选择 → 四个核心指标 → 总览 / 时间线 / 原始数据 Tabs。
- 四个指标为平均 Device 时间、P95、有效算力、有效带宽，单位与数值一起展示。模拟与估算性质不可省略。
- 总览采用稳定性 / Roofline 双列，再展示 kernel 排名和事件时长构成；窄屏变单列。
- 时间线保留固定引擎文字列、缩放、引擎筛选、依赖连线和事件明细；快捷键说明默认折叠。
- 原始数据、Chrome Trace 与 HTML 下载不删除；不会自动向外部工具上传数据。

### 5.7 Agent · 回归定位

**理念：先回答调查是否完成、找到什么，再展示证据过程。**

- 头部只有一个“新建调查”，上下文包含调查对象、记录选择和 mock 范围。
- 第一块为结果结论与关键版本 / 组件；随后为五步进度和版本轨迹。
- 最新环境通过时，仅展示已验证的基线 / 最新版本；日期定位和组件定位标记“无需执行”。不展示空组件矩阵、无效复现按钮或未执行搜索的占位内容。
- 出现目标失败时，展示版本范围、搜索过程、双向组件对照及最简复现；尚未验证的结论仍明确留空。
- 原始实验、日志、模型决策默认折叠；报告和证据包始终可在适用状态下载。
- 组件关联不等于源码根因或团队责任，相关范围保留一处清晰说明。
- Agent 侧栏仅展示可用的回归定位和模型配置；实验工作流接通后再开放入口。

### 5.8 诊断与证据

**理念：输入区明确对照对象，结果区只回答目标故障是否复现。**

- 基线、候选在同一行，下面为固定的目标故障判据与执行按钮。
- 不在同一页重复展示环境演示说明和“什么是诊断”的介绍。
- 结果与原始证据分组；脚本模型助手保持折叠。
- 当前仅界面演示时维持来源标记，不把模拟结果描述为真实责任定位。

### 5.9 数据中心

**理念：查询历史数据，使用一致的表格语言。**

- 我的任务 / 配置结果 / 公共 SDK / Daily 批次保持四个 Tabs。
- 任务类型和状态使用有名称的下拉选择；case 增加精确 Node ID 输入。筛选和查询按钮一行排列。
- 展示对象、类型 / 时间、结果、关联信息；长内部任务 ID 缩写，完整值保留 title，原记录仍可在业务页面查看。
- 日期、耗时使用清晰单位；状态用中文短名，避免把 completed、result 和 phase 原样重复打印。
- 个人空间不重复打印姓名；公共元数据保留一处“候选不等于门禁通过”的说明。
- 列表下方为记录数和加载更多；空态为一条短消息，不渲染示例数据冒充查询结果。

### 5.10 Agent · 模型配置

**理念：以命名配置为管理对象，密钥和版本按需处理。**

- 顶部为配置数量与新增按钮，不再重复“我的 AI 配置”标题。
- 表格展示名称、模型 / Provider、Key 是否保存、启用状态、编辑 / 验证。
- 默认配置使用短标签，revision 放进版本详情。Key 只显示有无，不展示明文或密文。
- 表单两列对齐；名称、Provider、模型、Key、默认 / 启用；远端 Provider 才展示 Base URL。
- 表单底部提供取消与保存，取消清除未保存 Key；成功提示不堆叠大面积色块。
- 真实 API 尚未启用必须直接写明，测试按钮不能伪造远端连接成功。

### 5.11 设置与姓名登录

**理念：账号操作清楚，用量是辅助信息。**

- 登录框只有姓名、进入按钮、演示入口；保留“同名进入同一空间，不验证身份”的短说明。
- 设置以姓名与切换用户为主行，用量改为紧凑清单，不以三个大卡片放大非关键数值。
- workspace ID 与身份边界放进空间信息详情；姓名登录仍不代表防冒名认证。
- 切换用户必须清理旧轮询和界面缓存，重新进入同名空间应恢复其历史。

## 6. 交互、可访问性与响应式

- 原生 button / select / input / details 维持语义；图标按钮必须提供可访问名称。
- 焦点使用 2px 青绿色 outline，offset 3px；不能为了简约删除焦点提示。
- 展开 / 收起状态使用 `aria-expanded` 或原生 details；可选标签标记当前状态。
- 错误用 `role=alert`，操作成功用 `role=status`；按钮执行中禁用，避免重复提交。
- 暂未获得结果显示未知或空态，不先显示模拟成功。下载失败反馈在当前模块。
- 740px 以下收起侧栏，表单单列、工具栏换行、图表单列；表格 / 时间线局部横向滚动，不使整个页面变宽。
- 长日志和原始 JSON 限高滚动；完整内容由导出或证据视图提供，不允许将整个页面变成无限日志。
- 遵循 reduced-motion 系统设置，不引入持续装饰动画。页面审核不等于完成屏幕阅读器 / 全浏览器认证。

## 7. 维护与验收

新增模块应依次回答：用户此刻要判断什么？唯一主要操作是什么？哪些信息必须常驻？哪些可以进入详情？未知和失败如何呈现？

公共样式用 `refine.css` token 和 `ui-*` 组件类；模块特有轨道、图表保留模块样式。不要继续在各文件末尾叠加同一套颜色和间距覆盖。当前旧模块样式仍保留，后续重构逐步将共用规则迁移到组件层。

验收清单：

1. 页面标题与关键结果位于第一屏，来源可识别。
2. 主要按钮没有重复，低频信息默认收起。
3. 展开后仍能找到原始证据、完整配置与导出。
4. PASS / FAIL / CRASH 标签清晰；未知、跳过、未执行不能伪装成成功。
5. 选择、筛选、Workers、复测、时间线缩放与固定列功能保持可用。
6. 桌面与窄屏检查实际渲染；键盘焦点可见，无根页面横向溢出。
7. 前端模型 / 会话测试、静态打包测试与生产构建通过。

本轮页面截图与检查记录见 [UI_REFINEMENT_QA.md](UI_REFINEMENT_QA.md)。

## Daily 增量

Daily作为独立主导航，默认月历：计划/月切换、红绿蓝灰状态、PASS/总数、耗时与复测徽标。月历仅填充必要的4–6周；颜色同时配文字。点击日期进入报告，顺序为状态/版本与复测入口→五步执行→六项指标→分类/算子质量→折叠快照→服务端筛选表→case数据库日志。部分复测单列来源，不覆盖日历。SDK/环境mock与历史未实际执行的范围置于标题下，不隐藏。布局和颜色沿用公共token，窄屏只允许配置表局部横滚。

### Daily 日历增量（2026-10-27）

日期格使用独立浅色卡片、16px圆角和10px间距，窄屏11px圆角/5px间距。每格按日期、PASS数量、耗时三级组织，不重复输出状态文案；状态点与图例辅助颜色辨识，完整状态放入可访问名称。保留Mock来源，复测规则放入悬停提示，详细质量口径在报告中展开。避免大段说明占据日历空间。
